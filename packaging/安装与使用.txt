WBBridge —— AI Passport 工牌 → WorkBuddy 中转服务
==================================================

工牌通过蓝牙把语音/操作发过来，这个程序在本机转成文字，再投递到
WorkBuddy 的对话框里。

它有两个入口，都是同一个东西：
  · 一个完整的主窗口（看状态、对话、录音、日志、设置）
  · 一个菜单栏图标（不占 Dock，随手开关服务）


安装
----
1. 把 WBBridge.app 拖到左边的「应用程序」文件夹（也可以直接在 DMG 里双击试跑，
   但装进 /Applications 之后权限记忆更稳）。
2. 想开机自动启动：系统设置 → 通用 → 登录项 → 「+」→ 选 WBBridge.app。
3. 首次双击会请求「蓝牙」权限 —— 必须允许，否则一碰蓝牙就会被系统杀掉。
   如果误点了「不允许」：系统设置 → 隐私与安全性 → 蓝牙 → 勾上 WBBridge。
4. 工牌开机后会自动连上（屏幕左上角出现电脑图标）。


界面（主窗口）
--------------
双击 App 就打开主窗口，左边五个页面：

  总览    三张状态卡（服务 / 工牌 / WorkBuddy）+ 最近对话 + 最近录音
          + 一排快捷操作（重新连接、发送测试、打开日志、重启服务）
  对话    本机所有 WorkBuddy 会话，点开看完整消息流；
          右上角可以按会话名搜索
  语音    每条录音一行：时长、大小、试听、重新转写、修改文字后重新投递
  日志    实时日志（等宽字体 + 按级别着色），可切「只看重要」滤掉心跳噪声
  设置    换 ASR 模型（tiny/base/small/medium）、语言，看运行环境
          （Python 路径、端口、PID、模型下载状态）

关掉窗口不会退出程序 —— 服务继续跑，点 Dock 或菜单栏图标再打开。


界面（菜单栏）
--------------
屏幕右上角有一个「波形」图标，三态：

    ⊙ 实心  服务在跑，工牌已连上
    ◯ 空心  服务在跑，等工牌
    ⊘ 划掉  服务停了

点它就是快捷入口：服务 PID、工牌地址和 MTU、对话条数，以及
「打开主窗口 / 重启服务 / 停止服务 / 打开日志 / 退出」。

没有 Dock 图标是故意的（它是常驻后台的小服务）。
如果菜单栏图标被刘海或别的图标挤掉了，关掉几个不用的菜单栏图标即可。


浏览器也能看
------------
主窗口其实就是本机的一个网页，任何浏览器都能打开同一套界面：

    http://127.0.0.1:8765/ui

端口不一定是 8765。服务启动时如果 8765 被别的程序占了，会自动往后挪
（8766、8767…最多试 20 个），真实端口写在：

    ~/.workbuddy/http.port

    # 想知道现在跑在哪个端口：
    cat ~/.workbuddy/http.port

深链接直接跳页：/ui#voice 录音、/ui#logs 日志、/ui#conversations 对话、
/ui#settings 设置。


运行环境
--------
服务本身用 Python 跑，需要这些包（已经装好的机器不用管）：

    pip3 install -r /Applications/WBBridge.app/Contents/Resources/bridge/requirements.txt

启动器会自动按顺序找解释器：环境变量 WB_PYTHON → bundle 内 venv →
~/.workbuddy/binaries/python/envs/default → Homebrew → 系统 python3，
选第一个能 import bleak / numpy 的。想指定就用：

    launchctl setenv WB_PYTHON /path/to/python3

首次语音转写需要 Whisper 模型（small 约 483MB），会自动下载到
~/.cache/huggingface；下载过一次就一直复用。设置页里能换模型。


常用操作（终端）
----------------
    wbctl start | stop | restart | status | log
    wbctl send "测试一句话" [会话id]    走工牌同一条链路发一条文本
    wbctl route [会话id]                看这条对话被路由到哪个网关实例

wbctl 就在 DMG 里，想全局可用：

    sudo cp /Volumes/WBBridge/wbctl /usr/local/bin/ && sudo chmod +x /usr/local/bin/wbctl


日志与数据
----------
    日志     ~/.workbuddy/wb_bridge.log
    录音     ~/.workbuddy/voice_out/*.wav
    端口     ~/.workbuddy/http.port
    网关缓存 ~/.workbuddy/.gw_cache.json

服务默认监听 127.0.0.1:8765，只对本机开放，不开外网。常用接口：

    curl -s 127.0.0.1:8765/status      状态（含 pid / port / uptime）
    curl -s 127.0.0.1:8765/ble         工牌连接详情
    curl -s "127.0.0.1:8765/logs?tail=50"   最后 50 行日志
    curl -s 127.0.0.1:8765/messages    对话消息（?size= &len=）


排错
----
· 弹「启动失败」：多半是缺 Python 依赖，主窗口的「打开日志」看最后几行。
· 一打开就闪退、日志里什么都没有：蓝牙权限没给，去系统设置勾上 WBBridge。
· 主窗口显示「服务未运行」：点页面里的「启动服务」按钮，或 wbctl start。
· 浏览器打开 8765 是别的页面（比如某个 MacCleaner 之类的工具）：端口被占了，
  服务已经自动挪到 8766，看 ~/.workbuddy/http.port 里的数字。
· 工牌显示「对话未打开」：网关只接受"窗口里装载着的那个会话"。你选的那条对话
  没在任何 WorkBuddy 窗口打开 —— 在电脑上把它点开再发，或改选列表里没标
  「未打开」的那条（列表已按"能投的排前面"）。想先确认：
      curl -s "127.0.0.1:8765/route?sid=<会话id>" | grep can_deliver
· 工牌显示「Session busy」：目标对话正在跑长任务，消息一直等不到空闲窗口。
  等它跑完再发，或投到别的对话。
· 电脑换了蓝牙适配器/系统升级后：删掉 系统设置 → 隐私与安全性 → 蓝牙 里的
  WBBridge 记录，重新双击授权。
· 彻底重置：退出程序 → 删 ~/.workbuddy/.gw_cache.json → 重新打开。
